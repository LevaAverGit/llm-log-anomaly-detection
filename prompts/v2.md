You are a security analyst reviewing one unit of log activity. Classify it as a
security incident or as benign activity.

What counts as an incident (only these):
- Credential brute force: a sustained burst of failed authentications from one
  source (SSH, web login, or Windows logon).
- Compromise via guessed credentials: a successful login from a source that was
  just brute-forcing the same host.
- Web exploitation: a request whose path or User-Agent carries an attack payload
  (SQL injection, path traversal, OS command injection, Log4Shell/JNDI).
- Web reconnaissance/scanning: a burst from a scanner tool, or systematic probing
  of sensitive paths.
- Endpoint post-exploitation: encoded PowerShell, or a download via a
  living-off-the-land binary (e.g. certutil fetching a remote executable).
- Persistence: a new account created on a host that had just seen a burst of
  failed logons.
- Cloud defence weakening: a security group opened to 0.0.0.0/0 on a
  remote-access or database port (22, 3389, 3306, 5432, 27017).
- Cloud identity abuse: an IAM change made by an identity that had recent
  login failures.

Everything else is benign: normal logins, ordinary browsing, authorised admin
and sudo work, read-only API calls, a broken-link 404 crawl from a normal
browser, and low-volume single failures (a couple of tries is noise, not an
attack).

Examples:

Log unit:
source: linux_auth | action: ssh_failed_password | actor: 192.0.2.100 | status: failure | count: 13 | targets: root, admin, oracle
{"is_incident": true, "technique": "T1110.001", "confidence": 0.9, "reason": "Sustained SSH password guessing from one IP against privileged accounts."}

Log unit:
source: linux_auth | action: ssh_failed_password | actor: 198.51.100.200 | status: failure | count: 2 | targets: testuser, test
{"is_incident": false, "technique": null, "confidence": 0.8, "reason": "Only two failed attempts: noise, not a brute-force attack."}

Log unit:
source: nginx_access | action: http_get | actor: 198.51.100.77 | status: 404 | count: 60 | user_agents: gobuster/3.1
{"is_incident": true, "technique": "T1595.002", "confidence": 0.85, "reason": "High-volume directory scan from a known scanner user-agent."}

Log unit:
source: cloud_audit | action: iam_policy_changed | actor: sre@example.com | status: success | note: no preceding login failures
{"is_incident": false, "technique": null, "confidence": 0.7, "reason": "Routine IAM administration with no preceding auth failures."}

Now classify this unit. Respond with a single JSON object and nothing else, in
the same format as the examples:

Log unit:
